# Nominication Module Design

**Pillar:** En (縁 — Community & Belonging)
**Date:** 2026-05-22
**Status:** Approved

---

## Overview & Philosophy

Nominication (飲みニケーション) is the Japanese practice of building community through shared social experiences — most commonly gathering after work over drinks. It is Kokoro's first En pillar module: turning passive cross-cultural friction signals into active community-building moments.

**Design principle:** Two existing systems, one intelligence layer.

- **Beer App** owns the social experience — groups, session voting, venue suggestions, RSVP, push notifications. Nothing changes here.
- **Kokoro** owns the intelligence — who should gather, why now, and what changed afterward.

Neither system is rebuilt. Kokoro adds a thin integration layer that reads friction signals, decides when a gathering would help, and measures whether it did.

**Three flows:**

1. **Manual** — anyone starts a Nominication from Slack, Google Chat, or Beer App directly
2. **AI-nudged** — Kokoro detects rising friction in a channel and suggests a gathering to the most-connected member
3. **Post-event** — attendance is confirmed, friction is correlated 14 days later, a light reflection prompt is sent

## Architecture

### System Diagram

```
Slack / Google Chat          Beer App (React Native)
        │                           │
  /nominication cmd          Gather UI (groups, voting, RSVP)
        │                           │
        └──────────┬────────────────┘
                   ▼
         API Gateway (NestJS)
         └── /nominication module
               ├── POST /sessions
               ├── GET  /sessions/:id
               ├── POST /sessions/:id/attend
               └── GET  /nudges/:userId
                   │
         ┌─────────┴──────────┐
         ▼                    ▼
   Nudge Engine          annotation-pipeline
   (Python, hourly)      (existing FastAPI)
   - reads friction        - supplies friction
     signals               signals to nudge engine
   - writes nudge queue
   - writes correlations
         │
         ▼
    PostgreSQL (4 new tables)
```

### New Components

| Component | What it does | Where it lives |
|---|---|---|
| `nominication` module | REST API for sessions, attendance, nudge queue | `api-gateway/src/nominication/` |
| Nudge Engine | Reads friction → decides who needs a gathering → writes nudge | New Python cron job (extend `feedback-learner`) |
| Beer App auth bridge | JWT issued by API Gateway, passed as Bearer token by Beer App | `api-gateway/src/auth/` (extend existing) |
| `/nominication` command | Slash command handler | `slack-app` + `google-chat-app` |

### Auth Flow — Beer App → Kokoro

```
Beer App login (Supabase)
    → user has Slack/Google identity
    → Beer App calls POST /auth/beer-token { slackUserId }
    → API Gateway issues short-lived JWT (15 min)
    → Beer App attaches to all Kokoro API calls as Bearer token
```

### What Does Not Change

- Beer App's groups, voting, venue, RSVP, push notifications — untouched
- All existing Kokoro services — additive only
- annotation-pipeline and feedback-learner existing consumers — no modifications
- Existing database tables — zero schema changes

## Data Model

4 new tables, all with `tenant_id` for multi-tenant readiness.

```sql
-- A gathering event (created from Slack, Google Chat, or Beer App)
nominication_sessions (
  id                UUID PRIMARY KEY,
  tenant_id         TEXT NOT NULL,
  channel_id        TEXT NOT NULL,
  initiator_id      TEXT NOT NULL,
  beer_app_group_id TEXT,                          -- nullable, links to Beer App group
  trigger_type      TEXT NOT NULL,                 -- 'manual' | 'ai_nudged'
  nudge_id          UUID REFERENCES nominication_nudges,
  scheduled_at      TIMESTAMPTZ,
  status            TEXT NOT NULL DEFAULT 'pending', -- pending | confirmed | completed | cancelled
  venue             TEXT,
  created_at        TIMESTAMPTZ NOT NULL DEFAULT NOW()
)

-- Who attended (written by Beer App POST /attend, or manually confirmed)
nominication_attendees (
  id           UUID PRIMARY KEY,
  session_id   UUID NOT NULL REFERENCES nominication_sessions,
  user_id      TEXT NOT NULL,
  confirmed_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
)

-- Nudges generated by the nudge engine
nominication_nudges (
  id             UUID PRIMARY KEY,
  tenant_id      TEXT NOT NULL,
  channel_id     TEXT NOT NULL,
  target_user_id TEXT NOT NULL,
  reason         TEXT NOT NULL,
  friction_score NUMERIC(5,2),
  status         TEXT NOT NULL DEFAULT 'pending', -- pending | accepted | dismissed | expired
  created_at     TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  responded_at   TIMESTAMPTZ
)

-- Post-event friction correlation results
nominication_correlations (
  id             UUID PRIMARY KEY,
  session_id     UUID NOT NULL REFERENCES nominication_sessions,
  channel_id     TEXT NOT NULL,
  friction_before NUMERIC(5,2),
  friction_after  NUMERIC(5,2),
  delta           NUMERIC(5,2),                  -- negative = improvement
  computed_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
)
```

**Indexes:**
```sql
CREATE INDEX ON nominication_sessions (tenant_id, channel_id);
CREATE INDEX ON nominication_sessions (beer_app_group_id) WHERE beer_app_group_id IS NOT NULL;
CREATE INDEX ON nominication_attendees (session_id);
CREATE INDEX ON nominication_nudges (tenant_id, channel_id, status);
CREATE INDEX ON nominication_correlations (session_id);
```

**En pillar score** — derived on-read, not stored. Computed from these four tables. No new column on the users table.

## Three Flows

### Flow A — Manual Initiation

**Via Slack / Google Chat:**
```
User types: /nominication #eng-cross Friday 7pm
    → slack-app / google-chat-app parses command
    → POST /nominication/sessions {
        channelId, initiatorId, triggerType: 'manual',
        scheduledAt, tenantId
      }
    → API Gateway creates session (status: pending)
    → Bot responds ephemerally:
        "✅ Nominication created for #eng-cross, Friday 7pm.
         [Send invite to channel] [Open in Beer App]"
    → "Send invite": bot posts channel message with RSVP deep link
    → "Open in Beer App": deep link → Beer App session view
```

**Via Beer App (direct creation):**
```
User taps "New Nominication" in Beer App group
    → Beer App calls POST /nominication/sessions (JWT auth)
    → Same session record created
    → Voting, venue, RSVP handled natively by Beer App
    → Beer App POSTs /sessions/:id/attend when attendees confirm
```

### Flow B — AI-Nudged Initiation

```
Nudge engine runs hourly:
    SELECT channel_id, AVG(friction_score), COUNT(*)
    FROM annotation_events
    WHERE created_at > NOW() - INTERVAL '7 days'
      AND tenant_id = $1
    GROUP BY channel_id
    HAVING COUNT(*) >= 3 AND AVG(friction_score) > 0.6

For each qualifying channel:
    → find most-connected member (highest event count)
    → INSERT nominication_nudges (status: pending)
    → send ephemeral via Slack / Google Chat:
        "📊 Kokoro noticed rising friction in #eng-cross this week.
         A team gathering might help bridge the gap.
         [Start a Nominication] [Dismiss]"

[Start a Nominication] → triggerType: 'ai_nudged', nudgeId attached
[Dismiss] → nudge status → dismissed, no retry for 14 days on same channel
```

### Flow C — Post-Event Tracking & Correlation

```
Step 1 — Attendance confirmed:
    POST /sessions/:id/attend { userId, attended: true }
    → writes nominication_attendees row
    → when all attendees responded OR 24h after scheduledAt:
        session status → 'completed'
        → enqueue correlation job (runs 14 days later)

Step 2 — Correlation job:
    friction_before = AVG(friction_score) WHERE
        channel_id = $1 AND created_at BETWEEN (session_date - 14d) AND session_date

    friction_after = AVG(friction_score) WHERE
        channel_id = $1 AND created_at BETWEEN session_date AND (session_date + 14d)

    → INSERT nominication_correlations { delta: after - before }
    → if delta < -0.15: log positive outcome

Step 3 — Light reflection (7 days post-session):
    → DM each attendee:
        "How did the team gathering go?
         [Much better] [A little better] [No change]"
    → response stored as feedback on the session record
```

## Dashboard Integration

### En Pillar Score — Computed on Read

```typescript
// GET /dashboard/en-score?userId=&tenantId=
{
  enScore: 72,
  breakdown: {
    sessionsLast90Days: 4,
    positiveCorrelations: 2,
    crossCulturalRatio: 0.75,
  },
  trend: 'improving'  // 'improving' | 'stable' | 'declining'
}
```

**Score formula:**
```
enScore = (
  min(sessionsLast90Days / 6, 1.0) * 40   // up to 40pts: activity
  + crossCulturalRatio * 35               // up to 35pts: diversity
  + min(positiveCorrelations / 3, 1.0) * 25  // up to 25pts: impact
) * 100
```

## Out of Scope

- Beer App venue booking or payment integrations
- Nominication scheduling conflicts / calendar integration
- Mandatory participation or manager-assigned sessions
- Real-time RSVP sync between Beer App and Slack (async only)
